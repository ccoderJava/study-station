# 项目长期约定

## 内容分类：agent 自己定，不要问用户

用户**不关注节点编号**（A1/B3/C6 这类）。约定：

- 新增卡片或场景题时，挂哪些节点、放 `cards/` 还是 `scenarios/`、`direction` 与 `event` 怎么填，**全部由 agent 判断**，不要向用户确认编号或归类。
- 对话里提到知识点一律用**中文名称**（「挂在服务治理和限流熔断」），不要甩编号。
- 判断依据：内容主体讲一个机制 → 卡片；跨 3 个以上知识点、有故障/设计冲突 → 场景题；`event` 按「简历关联 > 生产故障 > 项目实践 > 面试高频 > 体系补全」对号入座。
- 用户只需提供内容素材：题目、真实项目片段、想被追问的点。
- 用户给 GitHub 链接要「收藏 / 介绍仓库」→ 落 `content/repos/G编号-*.md`，走六段骨架（`FORMAT.md` 第 10 节）；star 等数字标抓取日期，非商用许可证必须写进 front-matter 与判断段。仓库卡片跟精读、面试一样不进复习队列。

## 用户偏好

- 沟通直接、少修饰，不要安慰式回答；指出问题要给可执行方案。
- 写作规范（七段式）已固化在 `FORMAT.md` 第 5 节，不要再问格式。
- 不代写 `## 我的口述记录`，那是他本人的复述练习。

## 技术约定

- 零第三方依赖是硬约束，不引入 npm/框架/CDN；`assets/` 是构建产物，只改 `theme/` 与 `content/`。
- 改完内容必须 `python3 build.py --check && python3 build.py` 并提交产物。
- 用 archify（`wrench-ai`）画图时，产出必须剥离 viewer 再落进 `theme/img/*.svg`：computed style 内联、去 class、切浅色主题、补浅底；不能直接把交互 HTML 放进站点。同页多张要给 `id` 加后缀，避免 `url(#grid)` 串图。细则在 `AGENTS.md` 画图节。

## 画图规则（2026-11-04 起，用户明确要求）

- **给站点画的任何图都必须落进文档**：写成 `theme/img/主题-用途.svg`，再用 `![图注](img/xxx.svg)` 单独成段插进卡片正文。只在对话里回图、或存 `/tmp`，视同没画。
- 插图**可点击放大**（全屏灯箱：滚轮缩放、拖动平移、双击复位、Esc 关闭）。所以内联状态也要能看清整体结构，别做成「必须点开才懂」。
- 图注写在方括号里，要一句能独立看懂；`build.py --check` 会校验图片文件是否存在。

## 代码块规则（2026-11-04 起）

- 代码块**必须带语言标识**（```java / ```sql / ```lua），否则不上色；ASCII 图用 ```text 或裸围栏。
- 高亮在 `build.py` 里构建期完成（`highlight()` + `CODE_LANGS` 表），不引入任何高亮库。加语言 = 往 `CODE_LANGS` 加一条关键字表。
- 颜色只走 CSS 变量 `--c-*`，四套配色由 `html[data-code]` 切换（light / dark / solar / monokai），页头「代码」下拉，选择存 `review-code-style-v1`。
