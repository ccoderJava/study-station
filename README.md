# Offer 斩杀（pay-review-station）

一个面向 **Java 后端 / 支付清结算方向** 面试复习的离线知识站。

内容全部是可版本管理的 markdown，构建成**零第三方依赖**的单页站点：双击 `index.html` 即可使用，可整体拷进内网。

---

## 快速开始

```bash
python3 build.py          # 构建（改完 markdown 跑这一条）
python3 build.py --check   # 只校验字段和引用关系，不生成
```

打开 `index.html` 即可。或用 `make serve` 起本地服务（`http://localhost:8787`），localStorage 存进度更稳定。

不需要 npm、不需要装任何包，Python 3 标准库就够。

## 目录结构

```
pay-review-station/
├── content/            内容的唯一来源，只改这里
│   ├── layers/         S1~S6     六层能力模型
│   ├── nodes/          A1~F4     33 个知识点节点
│   ├── cards/          A3-01-xxx 知识卡片（一个知识点一篇）
│   └── scenarios/      S01-xxx   场景题（一道题串多个知识点）
├── theme/              站点模板（index.html / app.js / style.css）
├── build.py            构建器（零依赖）
├── pack.py             打包成可拷进内网的 zip
├── FORMAT.md           内容格式规范 ← 写新内容前必读
├── index.html          构建产物，可直接打开
├── assets/             构建产物（data.js / app.js / style.css）
└── dist/               打包产物（offer-zhan-sha.zip，不进版本库）
```

`index.html` 和 `assets/` 是产物，改它们没用，每次构建都会覆盖。

## 知识点编号怎么看

站内所有关联（卡片挂节点、场景题连多个节点、图谱连线）都用**节点编号**表达，规则只有一条：

> **字母 = 第几层能力（A=S1 … F=S6），数字 = 该层里第几个知识点。**

`C6` 就是「第三层第 6 个」= 服务治理；`E1` 就是「第五层第 1 个」= 支付主链路。编号是固定的，改编号会断掉所有引用，所以新节点只能往后加。

| 层 | 编号 → 名称 |
|---|---|
| S1 语言与并发内核 | A1 集合与基础 · A2 并发基础 · A3 并发工具 · A4 JVM 与 GC · A5 线上问题排查 |
| S2 存储与数据 | B1 索引与 SQL · B2 事务与锁 · B3 分库分表 · B4 缓存设计 · B5 Redis 进阶 · B6 热点与缓冲记账 |
| S3 框架与服务 | C1 Spring 内核 · C2 Spring 事务 · C3 SpringBoot 扩展 · C4 MyBatis 插件 · C5 服务通信 · C6 服务治理 |
| S4 分布式 | D1 消息可靠性 · D2 分布式事务 · D3 分布式锁 · D4 限流熔断 · D5 可观测与发布 |
| S5 支付与财资 | E1 支付主链路 · E2 清算与结算 · E3 对账体系 · E4 账务与账户 · E5 资金安全 · E6 财资与司库 · E7 跨境与多币种 |
| S6 设计与架构 | F1 设计方法论 · F2 重构与迁移 · F3 稳定性工程 · F4 高并发场景 |

这张表是给查漏用的，日常不用记——新增内容时归类由 agent 判断。编号固定的原因是：卡片靠它引用节点，改编号会断路，所以新节点只能在层内往后排。

## 怎么新增知识点 / 场景题

两条路，选一条。

### 方式 A：自己写

1. **建文件**：卡片 → `content/cards/节点id-序号-标题.md`（如 `B5-02-xxx.md`）；场景题 → `content/scenarios/S15-标题.md`
2. **复制 front-matter**（字段定义见 `FORMAT.md` 第 2 节）：

```yaml
---
id: S15
title: "一句话标题，带具体场景"
kind: scenario
nodes: [C6, D4, E1]
primary: C6
direction: "系统设计"
event: "生产故障"
project: "某银行 / 某支付公司 / 某跨境电商中的真实片段"
level: core
status: draft
created: 2026-11-03
updated: 2026-11-03
---
```

3. **正文九段**，标题原样抄（七段强制 + 两段附加，见 `FORMAT.md` 第 5 节）：

```
## 30 秒简述
## 是什么
## 为什么这么设计
## 不用会怎么样
## 替代方案
## 项目中如何使用
## 常见陷阱
## 三层追问
## 我的口述记录
```

4. **构建**：`python3 build.py`，打开 `index.html` 看效果。

`nodes` 的取值决定它挂在哪个知识点、在图谱上跟谁连线；写多个 id 就会自动连成跨层线。连线多了也不必调整——图谱是力导向布局，会自动分散。

### 方式 B：把素材丢给 AI 整理（推荐）

**可行，但素材决定成稿质量**——AI 能补结构、补表达、补追问链，补不了你的项目细节。细节缺失时我宁可留 `（待补充）` 标出来，也不会编。

交给我的最小信息：

| 要给什么 | 说明 |
|---|---|
| 题目 | 一句话，如「Redis 热 key 打挂单分片」 |
| 类型 | 知识卡片，还是场景题（一道题串多个知识点） |
| 挂哪些节点 | **不用你操心**——我只按内容判断归到哪些知识点，你讲清楚题目和项目就行 |
| 真实项目片段 | 哪个系统、你做了什么、关键流程或数字 |
| 你想被追问的点 | 你答不利索的地方，我往那儿写 |

直接这样说就行：

> 加一道场景题：渠道日限额被打满，正常交易被拒。
> 项目是 某支付公司的渠道限额，当时用 Redis 计数 + DB 兜底，出过一个问题……

说清「题目 + 真实项目片段」就够了，归到哪些知识点由我判断。

口述也行：把想讲的先录音转文字，或者直接大白话打一段，我来拆成九段。

我会交付：新建的 md 文件 + 跑构建 + 更新覆盖率数字。**不做的两件事**：编造项目细节、代写 `## 我的口述记录`（那是你的复述练习，必须自己填）。

### 改完自检三条

1. `python3 build.py --check` 通过（字段、节点引用、id 重复）
2. 卡片页能打开，九段顺序正确
3. 路线图上对应节点从虚线变实线，图谱上出现新连线

## 导出到内网

站点零外部引用（无 CDN、无网络字体、无图片、无运行时请求），打包后拷过去就能用。

```bash
make pack          # = build + 打包，产物在 dist/offer-zhan-sha.zip
```

压缩包约 **385 KB / 112 个文件**，是全量包：页面、内容源文件、构建脚本都在里面。内网既能直接看，装了 Python 也能继续写卡片。

### 内网怎么打开

解压 → 双击 `offer-zhan-sha/index.html`。**用 Chrome 或 Edge**，不需要任何服务、不需要解压到特定目录。

实测过 `file://` 下的行为：内容正常渲染、localStorage 可写、刷新不丢。**不支持 IE11**（用了 `Element.closest()` 和 `Set`）。

如果内网要多人访问、或多个标签页共享同一份进度，再起个静态服务：

```bash
cd offer-zhan-sha
python3 -m http.server 8080      # 然后访问 http://<内网IP>:8080
```

### 学习进度不会跟着文件走

这是唯一需要手动的一步。进度存在浏览器 localStorage 里，换机器、换浏览器、清缓存都会丢。

```
本机：顶栏「数据」→「下载 .json」→ 存成一个文件（如 progress.json）
内网：打开站点 → 顶栏「数据」→「选择文件」→ 选中 progress.json →「合并导入」
```

导入是合并而非覆盖，按「上次复习日期 + 复习次数」取更靠前的那条，重复导入不会把进度改回去。所以可以在两台机器上各学各的，隔几天互相合并一次。

### 三个已知坑

1. **一台机器一份进度**：`file://` 下所有本地页面共用同一个存储区，多人共用一台电脑会互相覆盖。多人用就起上面的服务，各自用不同浏览器。
2. **别只拷 `index.html`**：它依赖同目录的 `assets/`（`data.js` 里是全部内容），单独一个文件打不开。
3. **安全扫描可能误报**：页面用 `innerHTML` 渲染，数据全部来自本地构建产物，无用户输入、无外部数据源，可据此说明。
