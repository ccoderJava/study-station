## 这个知识点要解决什么

一件事：**让一条 SQL 在数据量涨上去之后还是同一个耗时**。

索引不是「建了就能快」，它本质是拿「写的时候多维护一棵树」换「读的时候少扫很多行」。所以真正要判断的是三笔账：

- **要不要回表**：查的列在不在索引里，回表 N 次就是 N 次随机 IO。
- **一次能定位多少行**：最左前缀对不对、范围列在哪、`key_len` 用了几列。
- **优化器愿不愿意用**：选择性、回表比例、统计信息，这三项决定了它会不会主动放弃。

这三笔账串起来就是一条链：**B+ 树的结构 → 聚簇索引与二级索引的分工 → 回表 → 覆盖索引 / 索引下推 → 失效机制 → 优化顺序**。单独背每一段的结论没用，面试官往下追一层就露馅；能顺着这条链讲出「这条 SQL 现在走到哪一步、卡在哪」，才算讲明白。

## 面试常问角度

- 一张表能建几个聚簇索引？没有主键怎么办？
- 二级索引的叶子存什么？为什么是主键而不是行地址？
- 回表为什么慢？怎么避免？覆盖索引的代价是什么？
- 索引下推到底省了什么？为什么它不减少扫描行数？
- 联合索引 `(a,b,c)`，`where a=? and c=?` 算失效吗？`key_len` 是多少？
- 隐式转换为什么会让索引失效？「字符串列传数字」和「数字列传字符串」为什么结果不一样？
- `EXPLAIN` 里 `Using index` 和 `Using index condition` 有什么区别？
- 走了索引还是慢，可能是什么原因？
- 一条慢 SQL 摆在你面前，按什么顺序优化？
