## 30 秒简述

先把「不够」算准，再谈调度。**可用头寸 = 银行可用余额 + 在途收入 − 在途支出 − 冻结/保证金 − 已预约未执行**，很多所谓「头寸不足」是把冻结或已预约算了进去。确认不足后按**成本从低到高**四级调度：虚拟池内部调剂（零成本）→ 集团实体调拨（手续费低、T+0）→ 银行授信/透支（付利息）→ 同业拆借（成本最高、要审批）。技术上要解决三件事：调拨指令的时效（大额支付有截止时间，16:00 前必须发出）、跨行到账时间不确定（要靠查询 + 对账确认，不能假设实时）、**并行调度时的额度竞争**（同一笔余额被两个成员单位同时调度）。

## 是什么

1. **头寸口径分层**：账面余额（银行返回）、可用余额（扣冻结与保证金）、可用头寸（再扣已预约与在途支出、加在途收入）。三个数字必须分开展示，混在一起就是事故源头。
2. **在途识别**：在途收入 = 已受理未到账的收款（按回单预计到账时间）；在途支出 = 已发出未确认的付款（未知态单据按最坏情况算）。
3. **调度顺序**（成本优先）：
   - 虚拟池调剂：内部台账记账，不动银行账户，即时生效。
   - 集团下拨：集团户 → 成员单位户，同行实时、跨行看渠道。
   - 授信/透支：银行给集团的授信额度内透支，按日计息。
   - 拆借：同业或集团内部借贷，要走审批与合同。
4. **额度占用**：调度指令创建即占额（`占额表` + 条件更新），失败或撤销才释放；否则并发调度必然超调。
5. **截止时间**：大额支付系统有清算窗口，超级直连/银企直连的报文要在窗口关闭前发出；错过只能走次日，代发工资就会延迟发薪。
6. **执行与兜底**：调拨指令异步 + 未知态 + 按退避查询 + 日终对账核头寸，差额进挂账人工核。

## 为什么这么设计

资金有成本，缺钱要付利息，钱趴着损失收益，所以「算准 + 用最便宜的钱补」本身就是价值。分四级调度是因为不同来源的资金成本差 5~10 倍，先用贵的等于白扔钱。

代价是系统复杂度上升：要做头寸预测、要维护额度占用、要接多个资金来源、每条指令都要状态机与对账。只做监控告警（人来决策）就没这些复杂度，但响应速度跟不上支付窗口。

## 不用会怎么样

- 头寸算高：指令发出被银行退回，代发失败，员工当天拿不到工资——这是财资系统最严重的生产事故之一。
- 头寸算低：明明有钱还去拆借，白付利息；或者过度保守留大量备付金，资金效率低下。
- 不做额度占用：两个成员单位同时调度同一笔集团余额，后发的必然被退回，还要人工解释。
- 忽略截止时间：15:50 才开始调度，报文没发出去，只能等次日。

## 替代方案

| 方案 | 适用 | 说明 / 风险 |
|---|---|---|
| 预留缓冲（固定备付金） | 业务量稳定的小集团 | 最简单；资金利用率低，缓冲多少全靠拍脑袋 |
| 只做监控告警，人工决策 | 账户少、金额大 | 上线快；响应慢，夜间与节假日无人处理 |
| 规则化自动调度 | 多成员单位、日内频繁 | 主流；规则要防呆，必须留人工复核开关 |
| 银企现金管理产品（银行侧归集） | 想少自建 | 省开发；灵活性差，跨行支持有限 |

## 项目中如何使用

- **某银行财资系统**：头寸按「日终快照 + 每小时推算」双口径，快照给实时看板，日终口径用于对账；在途收入取「已受理未到账」的收款单据，按回单预计时间加权。
- **调度顺序落地**：先查虚拟池可用额度 → 不够再生成集团下拨指令 → 仍不够则按授信额度申请透支，每一级都有独立的额度表与审批规则。
- **一次真实问题**：两个成员单位在 14:00 同时发起调拨，都把集团户同一笔余额算成可用，第二笔被银行以「余额不足」退回。修复方式是引入**调拨占额表**——指令创建即原子占额（`update ... set used = used + ? where quota - used >= ?`），失败/撤销释放，人工可强制释放。
- **截止时间硬约束**：调度任务在 15:30 做一次「未完成指令」巡检，超时未发出的转人工并电话通知，绝不允许静默失败。

## 常见陷阱

- 把头寸等同于余额，忽略冻结、保证金、已预约——这是最常见的答错方式。
- 用「银行已受理」当到账：跨行调拨受理≠入账，中间可能有几十分钟到几小时，头寸要按未到账处理。
- 占额用「先查再更新」：并发下必然超调，必须条件更新或分布式锁。
- 面试官会追问「如果 16:00 前钱还是不到位怎么办」——答：降级方案（部分代发先发、剩余顺延并通知）、走授信透支、必要时启用备用账户，关键是**提前预警而不是到点才发现**。

## 三层追问

1. **怎么提前发现头寸不足？**——按时段滚动预测（9/11/14/16 点），对「预计支出 > 可用头寸」的时点提前 2 小时告警；大额付款要求提前一天预约。
2. **调拨指令发出去了但银行没回执？**——和支付一样走未知态：置 UNKNOWN、按退避查询、日终对账兜底，绝不重复发送。
3. **虚拟池调剂和实体调拨怎么选？**——能用虚拟池就用（零成本、即时），但它不改变银行实际余额，遇到真实对外付款时仍要实体资金到位，所以虚拟池解决「内部额度」，实体调拨解决「真实头寸」。
